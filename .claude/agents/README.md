# Agents

Four, and each one exists because of something that went wrong here more than
once. There is no architect, no reviewer, no generic tester: those roles do not
correspond to any failure this project has actually had, and an agent that is
not aimed at a real failure mode produces plausible output nobody acts on.

| Agent | When | Because |
|---|---|---|
| [`test-adversary`](test-adversary.md) | After writing any test meant to guard a fix, bound or invariant | Tests here have passed without testing anything at least four separate times, and every one was caught by accident |
| [`claim-auditor`](claim-auditor.md) | Before a release; after changing a bound, constant or API shape | "Not built: congestion control" survived three commits after it was built. The guards compile the code blocks and check the links; nothing checks the sentences |
| [`measurement-critic`](measurement-critic.md) | Before a number enters a document, or is used to choose a constant | Several published figures measured the harness rather than the system. `MAX_HANDSHAKES_PER_SECOND` shipped at two per cent of capacity |
| [`protocol-adversary`](protocol-adversary.md) | Before touching the handshake, session table, replay window or reassembly | Both denial-of-service holes were found by someone stopping to ask "what can a stranger do", not by any process |

## How they fit the existing guards

The repository already automates what can be automated, and CI runs all of it
on every push:

- `doc_snippets.rs` compiles every Rust block in README.md and USAGE.md
- `api_reference.rs` pins the constants and shapes API.md quotes
- `spec_conformance.rs` pins everything SPEC.md states normatively
- `malformed_input.rs` drives every parser with generated bytes
- `reliability_model.rs` drives the sender against the receiver
- `.github/check-links.py` resolves every link and anchor

These agents cover what those cannot. A guard can tell you a snippet compiles;
it cannot tell you the paragraph above it is false. A property test can explore
orderings; it cannot tell you it never reached the state that matters — that
took measuring the generator's reach, and is exactly the kind of question
`test-adversary` is for.

## The habit worth keeping regardless

Every fix in this repository is verified by **removing it and confirming the
test fails**. `test-adversary` makes that a step someone else performs rather
than one the author performs on their own work, which is the only reason it
works. Four versions of `reliability_model.rs` were written believing they
caught the bug they were aimed at. None of them did, and reading them would not
have told you.
